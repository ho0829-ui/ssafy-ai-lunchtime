# 학습 자료 → 퀴즈 (문제지·정답지 분리, 원문 근거 필수)

## 인자
`/make-quiz [자료 파일…] [문항 수] [유형 비율] [난이도]`

- 자료: .docx / .md / .txt (여러 개 가능). 없으면 첨부·연결 폴더에서 찾고, 그래도 없으면 파일을 요청한다.
- 기본값(사용자가 지정하지 않으면 묻지 말고 적용 후 결과에 명시): **10문항, 객관식 7 : 단답형 3, 난이도 중**.
- PDF·PPTX 등 다른 형식은 지원 범위 밖임을 한 줄로 알리고, 텍스트로 변환해 줄 수 있으면 변환 후 진행한다.

## 절차

1. **원문 색인 생성** — 반드시 스크립트로 한다. 원문을 직접 요약·재작성해 근거로 쓰지 않는다.
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/skills/make-quiz/scripts/extract_source.py <작업폴더> <자료1> [자료2 …]
   ```
   결과: `source_numbered.md`(문단마다 `[P12]` 번호), `source_index.json`(검증용).

2. **원문 정독** — `source_numbered.md` 전체를 읽는다. 문항 수 대비 분량이 부족하면(문단 수 < 문항 수) 문항 수를 줄이고 이유를 알린다.

3. **출제 계획** — 핵심 개념을 뽑아 문항에 배분한다. 한 문단에 문항을 몰지 말고 자료 전체 범위를 고르게 덮는다. 세부 규칙은 `references/item-writing.md`를 읽고 따른다.

4. **quiz.json 작성** — 스키마는 `references/quiz-schema.md`. 핵심 규칙:
   - 모든 문항에 `evidence` 1개 이상. `quote`는 해당 `pid` 문단에서 **글자 그대로 복사**한 연속 구간(5자 이상, 가급적 1~2문장). 의역·생략부호(…)·오타 수정 금지.
   - 근거는 "정답이 왜 정답인지"를 직접 뒷받침하는 문장이어야 한다. 주제만 같은 문장은 근거가 아니다.
   - 원문에 근거가 없는 문항(배경지식·추론만으로 푸는 문항)은 출제하지 않는다.
   - 객관식 정답 번호를 고르게 분산한다.

5. **검증·렌더링**
   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/skills/make-quiz/scripts/build_quiz.py <작업폴더>/quiz.json <작업폴더>/source_index.json <출력폴더>
   ```
   - `[오류]`가 나오면 파일이 생성되지 않는다. 메시지대로 quiz.json을 고치고 통과할 때까지 재실행한다. 인용 불일치 시 원문에서 다시 복사한다(스크립트가 실제 위치를 알려주면 `pid`를 고친다).
   - `[경고]`는 검토 후 타당하면 수정, 의도된 것이면 유지.

6. **자체 검토** — 통과 후 정답지를 열어 각 문항을 확인한다: 정답이 유일한가, 근거 인용만 읽고도 정답이 확정되는가, 문제지에 정답·힌트가 새지 않았는가. 문제가 있으면 4~5단계 반복.

7. **전달** — `<제목>_문제지.md`, `<제목>_정답지.md` 두 파일을 보낸다. 사용자가 폴더를 지정했으면 그 폴더에 저장한다. 응답에는 문항 수·유형 구성·적용한 기본값만 짧게 적고 문항 내용을 반복하지 않는다.

## 금지
- 문제지 파일에 정답·해설·근거를 넣지 않는다(스크립트가 분리하므로 quiz.json의 `stem`/`choices`에 정답 단서를 쓰지 않는 것만 주의).
- 검증을 건너뛰고 Markdown을 직접 작성하지 않는다.
